# F-036: Agent 流式响应与素材操作区修复

## Goal

让求职 Agent 在不同屏幕宽度下充分利用可用空间并逐块展示模型输出，同时简化素材库中无实际使用价值的操作，避免按钮随内容宽度漂移。

## User scenarios

- 用户在宽屏或窄屏打开求职 Agent，页面和回答区域随主内容区宽度变化。
- 用户发送问题后，回答随着服务端增量事件持续显示，而不是请求结束后一次出现。
- 用户在素材库选择卡片后，始终能在固定操作区找到编辑和删除，并可保存新文案版本。

## In scope

- 移除 Agent 页面 1480px 最大宽度限制，消息容器使用可用宽度并保留响应式内边距。
- 修正流式消息的 Vue 响应式引用，并用帧级缓冲将网络 delta 稳定呈现为连续打字效果。
- 合并高频自动滚动，避免每个网络分块重复启动平滑滚动和整段 Markdown 重绘。
- 素材详情头部将操作按钮放入独立等距容器，仅保留编辑和删除。
- 删除素材库“归档”“查看影响”及其关联的筛选、弹窗和前端请求入口。

## Out of scope

- 不修改模型、Prompt、对话持久化结构或 Provider 配置。
- 不删除归档、影响预览和同步相关服务端 API 或历史数据。
- 不重构素材卡片的数据模型和版本保存流程。

## Acceptance criteria

- Agent 根容器宽度始终为主内容区的 100%，宽屏不再被 1480px 上限截断。
- Assistant 消息区域随容器伸缩；移动端无横向溢出。
- 收到首个有效文本后即可看到内容，后续 delta 以稳定打字节奏持续追加；孤立的 `#`/`##` Markdown 前缀不单独闪现或停驻。
- 高频分块仅按动画帧批量触发 Markdown 重绘与自动滚动，停止和错误信息仍正常显示并完整保存。
- 素材详情的编辑、删除按钮位于同一操作组，间距固定且不会被 `space-between` 分散。
- 素材库页面不再出现归档、显示已归档、查看影响和影响预览弹窗；保存新版本功能保持可用。
- `pnpm test:career-agent`、`pnpm typecheck`、`pnpm lint` 和 `pnpm build` 通过。

## Affected contracts

- 无。现有 HTTP API 与领域模型保持不变。

## Risks and open questions

- 宽屏回答行长可能过长；通过内容区内边距和 Markdown 排版控制可读性，不重新引入固定页面上限。
- 服务端已设置禁用代理缓冲的响应头；保留现有 NDJSON 协议，在前端解耦网络分块与视觉输出节奏。
