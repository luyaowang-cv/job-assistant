# F-007: 增强官网表单字段上下文识别

## Goal

让扩展能够从企业官网常见的组件式表单中稳定取得字段标签，使本地高置信规则有可匹配的输入，而不是把多数控件报告为“未命名字段”。

## User scenarios

1. 用户在北森、Element Plus、Ant Design 或表格布局的网申页面点击“识别并填写当前页面”。
2. 扩展从字段关联 `label`、ARIA 属性、最近的表单项标签、相邻可见标签和短上下文中提取一个可解释的标签。
3. 姓名、联系方式等已有高置信规则的字段恢复正常匹配；年龄可由完整出生日期本地计算；原生下拉框仅在存在唯一精确选项时自动选择。内推码、未知问题、重复经历、日期、复选/单选和敏感字段仍明确保留人工处理。

## In scope

- 在用户显式点击后的页面扫描中，补充 `label[for]`、包裹标签、ARIA、Element Plus/Ant Design/通用 `.form-item`、表格行和相邻标签的字段标签提取。
- 仅传回必要的可见标签/短上下文、属性名、控件类型和选项标签；不读取、返回或存储现有表单值。
- 规范化必填星号、末尾冒号等装饰字符，并用本地 fixture 覆盖组件式布局。
- 基于通用资料中的完整出生日期本地计算年龄；为原生单选 `select` 增加唯一精确选项匹配，不匹配、多选和自定义下拉组件继续手动处理。
- 为新增规则补充单测、构建和手工验收步骤。

## Out of scope

- 不引入常驻 content script、`<all_urls>` 权限、页面滚动、解除 disabled/readonly、自动点击、自定义下拉项、上传或提交。
- 不把未确认字段发送给 AI，也不在本功能中接入 API Key 或产生外部模型费用。
- 不读取或报告原页面已有输入值；内推码、身份证号、密码、验证码、隐私授权等敏感/未知字段不自动填写。

## Acceptance criteria

1. 组件式 fixture 中的姓名、手机号、邮箱、所在城市可获得标签并按既有安全规则填写；标准 `label` 页面不回归。
2. 字段标签提取遵循明确优先级，文本会去除必填星号、末尾冒号等装饰；过长或无法判断的容器文本不作为可自动填写依据。
3. 完整出生日期能按当天本地日期计算年龄；原生单选下拉框仅在值与一个可用选项精确相等时选择，其他下拉/单选、日期、重复或敏感字段继续保守处理。
4. 扩展单测、构建通过，且用户在目标官网复测时“未命名字段”显著减少；未能确认的字段保持手动提示。

## Risks and open questions

- 某些官网的可视控件是自定义 `div` 或 iframe，无法安全处理时必须仍报告手动处理。
- 框架容器可能包含辅助文案；只有独立、短且可归属的标签可参与高置信匹配。
