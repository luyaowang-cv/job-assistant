# F-002：岗位评估与投递准备 Agent

## Goal

让用户对已保存的岗位主动发起 AI 评估。Agent 结合岗位 JD、用户粘贴的当前简历文本和可编辑求职偏好，输出可解释的投递判断与准备建议；每次分析均可追溯，但不保存完整简历原文，也不替用户执行投递或修改数据。

## User scenarios

1. 用户在 F-001 的投递详情中点击“AI 评估岗位”。
2. 用户粘贴当前简历文本，确认或编辑自己的求职偏好后发起评估。
3. 用户看到岗位核心要求、匹配证据、缺口/风险、匹配分、投递优先级与投递前准备建议。
4. 用户在同一岗位上修改简历后重新评估；新结果作为独立历史记录保存，不覆盖旧记录。
5. 用户在岗位详情中查看最新评估结果和历史记录，并自行决定是否投递、修改状态或进入材料准备。

## In scope

- 在 Application 详情抽屉提供“AI 评估岗位”入口、简历文本输入与运行状态展示。
- 可编辑的单用户求职偏好卡片，默认预填：前端开发、Agent 开发、AI 前端开发；北京；互联网、国企央企、私企、研究院；Vue 3、工程化、AI 应用等方向。
- 以 LangGraph.js 实现受控工作流：JD 结构化解析 → 偏好对照 → 简历证据映射 → 缺口/风险分析 → 优先级决策 → 投递准备建议。
- 每次运行生成可追溯的 AgentRun，保存关联岗位、偏好快照、简历摘要或哈希、结构化结果、模型信息、耗时、状态与错误信息。
- 结果固定包含：岗位核心要求、简历匹配证据、缺口/风险、0–100 匹配分、投递优先级、投递前准备建议。
- 优先级为：高优先级（建议尽快投）、中优先级（准备后投）、低优先级（备选）、不建议投（硬性条件明显不满足）；必须附带理由和证据。
- LLM 只能读取经 Zod 校验的岗位、偏好和本次提交的简历文本；不得直接访问 Prisma、SQL、文件系统、环境变量或外部账号。
- 运行期间展示明确的加载、成功与失败状态；失败结果保留错误元数据，用户可以再次发起评估。

## Out of scope

- 自动发现、爬取、批量采集或自动投递岗位。
- 生成打招呼话、求职信、简历改写或导出简历（F-003）。
- 永久保存完整简历原文、简历版本管理或文件上传（F-003）。
- 自动创建投递、自动修改 Application 状态、发送提醒或外部消息。
- 多用户账户、跨用户共享分析结果。
- 公司调研、面试题生成与模拟面试。

## Acceptance criteria

1. 用户能从任一已保存 Application 的详情中打开“AI 评估岗位”入口。
2. 用户必须提交非空简历文本；缺少 JD 或简历文本时，服务端以统一错误格式拒绝运行。
3. 用户可查看和编辑默认求职偏好；该偏好仅归属当前 local user。
4. 每次成功运行都返回并展示六类结果：岗位核心要求、匹配证据、缺口/风险、匹配分、优先级、投递前准备建议。
5. 每项匹配结论至少包含来自 JD 或用户简历的可识别依据；不得虚构用户经历、技能、项目、数据或职位要求。
6. 同一岗位连续运行两次后，历史中保留两条独立记录，且可查看各自的创建时间、模型、运行状态和结果。
7. 系统不持久化完整简历文本；保存的 AgentRun 不含可还原完整简历的正文。
8. Agent 不会创建投递、改变投递状态、改写简历或执行任何外部副作用。
9. Agent 工具输入输出均经 Zod 校验；用户只能访问当前 local user 的偏好、Application 与 AgentRun。
10. AI 调用或结构化解析失败时，页面展示可重试错误，不影响已有投递记录和历史评估结果。

## Affected contracts

- `specs/contracts/domain-model.md`：新增或细化 JobPreference、AgentRun 与 Application 的关联。
- `specs/contracts/agent-tools.md`：明确 runJobMatch 的输入、输出、可读范围与无副作用约束。
- `specs/contracts/api-conventions.md`：新增 F-002 Agent Run、偏好读取/更新 API 契约。
- 后续新增：F-002 的 LangGraph 状态、节点输入输出与 Provider Adapter 契约。

## Confirmed decisions

- F-002 名称为“岗位评估与投递准备 Agent”，不是爬虫或岗位发现功能。
- 岗位来源为用户手动录入或后续 Chrome 插件保存；Agent 只分析用户已确认保存的岗位。
- 用户在每次运行时粘贴当前简历文本；完整原文不永久保存。
- 每次重新评估都保留历史，不覆盖旧结果。
- 入口位于岗位详情抽屉；完成后在详情中显示最新结果和历史记录。
- Agent 只输出建议；生成话术、简历优化和任何写入动作留给后续 Feature。
- MVP 使用本地 Mock Provider 生成确定性的结构化评估结果；不配置 API Key、不调用外部 LLM、不发送 JD、简历或偏好到第三方。后续真实 Provider 仅替换 Adapter 实现。
