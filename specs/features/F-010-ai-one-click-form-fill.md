# F-010: AI 一键网申填写

## Goal

用户在任意网申页面点击扩展“填写”后，插件将普通空白表单字段交给工作台配置的 AI 进行语义映射并自动填写；填写成功的字段标浅绿色，AI 未能填写的普通字段标浅红色。

## User scenarios

1. 用户选择一份网申资料档案，在企业官网表单点击“填写”。
2. 扩展扫描可见字段的标签、短上下文、控件类型和选项，但不读取已有字段值。
3. 工作台使用统一 OpenAI 兼容 Provider，根据所选档案为普通字段生成填写建议；扩展在同一次用户操作中自动应用建议。
4. 成功写入的字段显示浅绿色；普通空白但无答案/无法应用的字段显示浅红色；用户仍自行检查并提交。

## In scope

- 用户显式点击后的一键“扫描 → AI 映射 → 自动填写 → 绿/红高亮”流程。
- 文本、文本域、日期和原生单选下拉的 AI 建议填写；下拉支持唯一精确匹配，或唯一包含匹配。
- 工作台端 OpenAI 兼容调用、Zod 请求/响应约束、超时和可恢复错误；使用 F-009 的设置与服务端 Key。
- AI 仅收到所选档案和无值字段描述；页面既有输入值不读取、不发送、不报告。

## Out of scope

- 不填写密码、验证码、银行卡/支付、文件上传、隐私/法律授权控件；不自动提交、跳页或发送消息。
- 不覆盖页面已有内容；不处理跨域 iframe、验证码或需要复杂点击链的自定义控件。
- 不持久化 AI 的页面字段建议、原页面字段或完整 Provider 响应；不进行 Key 连通性测试页面。

## Acceptance criteria

1. 点击扩展“填写”后，普通空白字段会调用工作台 AI 映射并在同一次操作中自动填写；未配置 Key 时显示可恢复设置提示。
2. 成功填写字段为浅绿色，AI 无答案、无匹配选项或填写失败的普通空白字段为浅红色；已有和敏感字段不改色、不覆盖。
3. API 的 Zod schema 拒绝未知字段、未选择档案、敏感控制类型和不受限的字段数量/文本；返回值只包含允许的 fieldId/value。
4. 扩展不保存 Key，不引入全站权限或常驻脚本，不自动提交；自动测试、类型检查和扩展构建通过。

## Risks and open questions

- AI 语义映射有成本且可能产生错误答案；用户要求一键自动填写，结果以绿/红高亮供其快速复核。
- 不同官网的自定义下拉组件结构不一；本 Feature 先保证原生控件，后续基于真实页面添加适配器。
