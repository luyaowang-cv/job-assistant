# F-048: 归属与冲突拦截

> 属于总纲 F-047 的 P0 功能点。目标 G1：**误填率为 0**。

## Goal

规则层现在**分不清"谁的"**。它按标签的字符包含关系打分，于是任何含「姓名」「手机号」「联系电话」的框都会命中 `basics.*`——包括父母、配偶、推荐人、证明人的框。

实测（`buildFillPlan`，档案只存本人姓名与手机号）：

| 页面字段 | 当前结果 |
|---|---|
| 父亲手机号 | 本人的手机号 ❌ |
| 家庭联系电话 | 本人的手机号 ❌ |
| 家长姓名 / 联系人姓名 / 推荐人姓名 / 证明人姓名 | 本人的姓名 ❌ |
| 父亲电话 / 家庭成员电话 | 空（不是因为识别对了，而是「电话」这个别名恰好匹配不上） |

唯一挡住这类错误的现有机制是两处**巧合**：`isDescriptorCompatible` 里一行针对"国家区号"的正则，以及「同一栏目已被占用」的去重——后者与字段在页面上的先后顺序绑定，把「父亲姓名」挪到「姓名」前面就会被填。本次要把它们替换成一条机制。

**这是总纲里唯一不可让步的指标**：填错要用户逐项删，且会让人不敢再用；填不上只是留个待办。

## User scenarios

- 网申表单填到"家庭信息"一节，问「父亲姓名」「父亲手机号」。档案里没有对方的信息，**这四个框保持为空**，并在报告里写明"档案里没有该归属的值"，而不是"规则未识别"。
- 用户确实在档案里存了紧急联系人姓名与电话，页面问「紧急联系人姓名」「紧急联系人电话」，这两项**正常填上**，并且不与本人信息串。
- 页面上同时有「联系电话」和「推荐人手机号」，只有前者填本人的号码。
- 一个字段的标签同时能被两条规则解释（例如既像"籍贯"又像"生源地"），且两条规则分差极小——**不猜**，标为「需手动确认（规则冲突）」，也不送给模型。

## In scope

- **归属域（attribution）**：规则表每条规则标注归属（`self` / `other`），字段侧由描述符推断归属；两侧不一致时不打分。他人标记词取多字词（父亲/母亲/家长/配偶/子女/家庭成员/家庭/紧急联系人/联系人/推荐人/证明人/介绍人/担保人/监护人/亲属/家人），**不使用单字**（父/母/子/女），以免误伤公司名、项目名。
- **他人规则显式化**：`basics.emergencyContact*` 三条标为 `other`，并只在字段含他人标记时生效——避免它们去抢一个普通的「姓名」框。
- **归属原因进报告**：因归属不符而留空的字段，原因写「档案里没有该归属的值」或「这是他人信息，本人档案不提供」，与"规则未识别"区分开。
- **分差闸门**：`bestRuleFor` 取前两名，分差低于阈值时不返回规则，落成 `needs_manual`，并把两条候选写进原因；**该字段不进入 AI 候选列表**。

## Out of scope

- 新增其他人员的数据结构（家庭成员的姓名、关系、电话不新增档案字段）。本次只保证**不填错**，不保证填得上。
- 多记录场景下的归属（两段实习各自的联系人）——属 F-049。
- 页面三色标记（需确认的字段怎么显示）——属 F-054。

## 验收标准

- AC-1：档案只存本人姓名与手机号时，`父亲姓名`、`父亲手机号`、`家长姓名`、`联系人姓名`、`推荐人姓名`、`证明人姓名`、`推荐人手机号`、`家庭联系电话`、`家庭成员电话`、`配偶手机号` **全部为空**，状态为「需手动确认」，原因包含"他人"或"该归属无值"。
- AC-2：档案同时存有紧急联系人姓名与电话时，`紧急联系人姓名`、`紧急联系人电话` 分别填上对应值；同页面的 `姓名`、`手机号` 仍填本人值；四者互不交叉。
- AC-3：把 AC-1 里的他人字段排到 `姓名`/`手机号` **之前**，结论与 AC-1 完全一致（**顺序无关**）。
- AC-4：构造一个两条规则分差低于阈值的字段，状态为 `needs_manual`、`skipAi === true`，原因列出两条候选规则；该字段不出现在送给 AI 的字段列表里。
- AC-5：因归属不符而留空的字段，报告原因为「他人信息」类文案，而不是「字段含义无法可靠确认」。
- AC-6：现有 124 条测试全绿；北森 dump 回放后 `filled` 计数不低于改动前（不允许把原本能填的字段挤进人工）。

## Risks and open questions

- **「联系人」可能指本人**：部分表单里"联系人"就是申请人自己。按"宁可空不可错"，本次一律留空；若实际使用中发现某站点「联系人」确实指本人，按站点补例外并在契约里记一条，而不是放宽全局。
- **分差阈值**：初值 0.05（精确 0.99 与包含 0.91 之间留半步）。用北森 dump 回放统计转人工比例，超过两成就下调。
- **他人标记词误伤**：「家庭」出现在「家庭住址」里——住址是本人的，不能被判成他人。因此在归属判定里，`住址/地址/籍贯/户口` 这类词出现时**不触发他人归属**。

## 实施记录（2026-10-19）

**动手前先用测试确认了三条错误行为**（`form-fill-rules.test.js`，修复前三条 `not ok`）：父亲姓名/家长姓名/联系人姓名/推荐人姓名/证明人姓名被填成本人姓名；父亲手机号/家庭联系电话/推荐人手机号被填成本人手机号；他人字段的状态还随页面顺序变化——说明当时挡住它的确实是「同一栏目已占用」的去重，而不是归属。

**归属层落地**：`OTHER_PERSON_PATTERN` + `SELF_CONTEXT_PATTERN` + `attributionOfDescriptor` / `inferAttribution`，在 `scoreRule` 的结构性否决里与 `isControlCompatible`、`isDescriptorCompatible` 并列。三条紧急联系人规则标 `attribution: 'other'`。

**一处踩到的边**：「紧急联系电话」不含「紧急联系人」四字，第一版漏判，导致一条既有测试（`fills explicit local-only identity and emergency-contact labels`）失败。把标记词从「紧急联系人」放宽成「紧急」，既有测试恢复、新行为不变。

**分差闸门**：`SCORE_MARGIN = 0.05`。实测在「开始时间 / 结束时间」无段落线索时触发（教育与实习平票），在有段落线索时不受影响（新增用例锁定）。

**回放验证**：北森 dump（`beisen-zhiye-camzhaopin.json` + `example-profile.json`）在 `SCORE_MARGIN` 为 0 与 0.05 两种配置下结果完全一致——`filled 5 / skipped_existing 11 / needs_manual 21 / 送模型 3`，**没有把任何原本能填的字段挤进人工**。

**测试**：基线 124 条 + 新增 7 条 = **131 条全绿**。
