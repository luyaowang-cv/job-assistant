# F-045: 今日工作台数据化重构

## Goal

把今日工作台从"手填字段驱动的提示板"改成"自动推导的数据面板"。原页面的核心模块「今日重点」依赖 `nextAction` 字段，而该字段在 110 条投递中填写数为 0——模块自上线起就没有显示过任何数据。本次改为全部由投递状态与操作事件自动推导，并补上转化漏斗、每日投递等真正在增长的数据视图，同时清掉三处互相重复的模块。

## User scenarios

1. 用户打开首页，直接看到今天投了多少、本周投了多少、有多少件事值得优先推进，不需要自己填任何字段。
2. 用户在「今日重点」里看到按紧急度排好的待跟进投递，点开任意一条即可查看详情并直接改状态，不必跳到投递看板来回横跳。
3. 用户通过转化漏斗看到自己投出去的记录到底有多少走到了笔试和面试。
4. 用户通过每日投递柱状图看到自己最近一个月的投递节奏，以及最近是否断了。

## In scope

- 新增聚合接口 `GET /api/v1/dashboard/summary`，一次返回概览数字、转化漏斗、投递节奏和待跟进清单。
- 转化漏斗改用**事件历史口径**：用 `ApplicationEvent` 的状态变更还原"到达过某阶段"，而不是只看当前状态快照。
- 「今日重点」改为自动推导：不依赖 `nextAction`，按「面试中 / 笔试中 / 准备中 / 已投递≥14天 / 收藏≥30天」分档排序。
- 概览区改为格栅三列一行：重点卡 + 今日投递 + 本周投递。
- 新增「每日投递」柱状图（近 30 天，含零值空槽）。
- 删除三处重复模块：「行动轨迹」「正在推进的机会」表格、「资料入口」卡片组；并删除「最近推进」小卡片与今日重点行首的装饰圆圈。
- 今日重点行改为打开投递详情弹窗；弹窗复用岗位库的 `job-detail__*` 版式，投递状态改为可编辑下拉框。
- 修正概览卡片两个错误的统计数字。

## Out of scope

- 不新增数据库模型或迁移；`ApplicationEvent` 已有的事件结构足够支撑本次全部口径。
- 不改动投递看板、岗位库、素材库、简历版本等其他页面的功能。
- 不改 Element Plus 主题主色（紫色问题见 F-044 的遗留问题记录）。
- 不做首页之外页面的布局调整。

## Acceptance criteria

- 概览卡片显示真实的「正在跟进」「已保存投递记录」数量，不再被列表用的 `slice()` 和 `pageSize` 上限截断。
- 概览区在 1024px 及以上始终是 grid 三列一行，重点卡宽度始终约为行宽的 1/3，不出现横铺整行的档位；900px 及以下改单列。
- 转化漏斗的每档数字为"到达过该阶段"的累计人数；能计入"进过笔试但后来被拒"的记录，数字不小于按当前状态统计的结果。
- 「今日重点」在 `nextAction` 全为空时仍能列出条目；排序为阶段优先（面试中 → 笔试中 → 准备中 → 久投无动静 → 久藏未投），同档内按停滞天数降序；上限 8 条。
- 每条今日重点的说明文字说明"为什么在这里"，不与该行右侧的状态标签重复。
- 「每日投递」展示近 30 天每日投递量，无投递的日期显示为空槽而非消失；结论句给出窗口内总量与距最近一次投递的天数。
- 右侧「每日投递」卡片的底边与左侧「今日重点」卡片底边对齐，且不依赖写死的图表高度。
- 点击今日重点任意一行打开投递详情弹窗，不跳转页面；弹窗内展示岗位信息、投递注意事项、公司介绍；状态下拉框改动后立即落库并刷新页面数据。
- 状态改动通过 `/api/v1/applications/:id/status` 写入，确保产生状态变更事件。
- 首页不再出现「行动轨迹」「正在推进的机会」「资料入口」「最近推进」；侧边栏已覆盖的入口不重复出现。
- 首页只发起一个聚合请求，不再单独拉取 100 条投递快照。
- `pnpm lint`、`pnpm typecheck`、`pnpm build` 通过。

## Affected contracts

- **新增**：`GET /api/v1/dashboard/summary`。查询参数 `dayStart`、`weekStart`（ISO 字符串，由前端按浏览器本地时区计算），返回概览数字、漏斗分档、节奏数据与待跟进清单。
- **复用不改**：`GET /api/v1/applications`、`GET /api/v1/applications/:id`、`PATCH /api/v1/applications/:id/status`。
- 状态写入沿用既有 `source` 枚举，弹窗改动标为 `DETAIL`。

## Risks and open questions

- **取代 F-017 的部分决定。** F-017 规定首页展示「今日重点 + 三条推进机会 + 资料入口」，其中推进机会表格的"四列、只显示前三条"验收标准本次被删除。原因是那三条数据与「行动轨迹」用的是同一个变量、同一个 `slice(0, 3)`，属于同一份数据渲染两遍；「资料入口」则与侧边栏完全重复。
- **取代 UI-DESIGN-SYSTEM 的首页三档布局。** 该文档规定"中等桌面为重点卡整行"，本次按需求移除该档位，概览区在任何宽度都是一行三列（900px 以下单列）。
- **「每日投递」窗口为 30 天常量。** 窗口取 7 天会得到一张几乎全平的图（实测最近一周投递为 0），但 30 天在 1024px 下每根柱子只有约 7px。窗口大小在 `dashboard.service.ts` 的 `DAILY_WINDOW` 常量中调整。
- **漏斗口径依赖事件完整性。** 直接以"已投递"状态创建、或历史导入的记录可能没有对应的状态变更事件，漏斗最上方两档会略低于按当前状态统计的数字。实测差 3 条（64 vs 61）。
- **前端传入日期边界。** 服务端可能是 UTC 容器（`docker-compose` 未设 `TZ`），"今天/本周"若由服务端计算，早 8 点前会显示成前一天，因此边界由前端算好传入。
