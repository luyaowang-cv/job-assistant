# F-035: 岗位库与投递看板列表重构

## Goal

让用户在岗位库和投递看板的列表中快速识别关键岗位信息，并在不离开当前上下文的情况下查看完整岗位资料。

## User scenarios

- 用户按地点和企业性质筛选岗位，通过更新时间判断信息新鲜度。
- 用户点击岗位库列表行，通过弹窗阅读岗位详情、投递注意事项和公司介绍。
- 用户从岗位库将岗位加入投递看板，重复操作不会创建重复记录。
- 用户在投递看板按当前阶段筛选，并从列表查看更新时间、下一步和内推码。
- 用户在投递详情抽屉查看或维护投递注意事项与公司介绍。

## In scope

- 重排岗位库列表字段为：更新时间、公司/岗位、工作地点、行业/性质、公告/投递、内推码、操作。
- 岗位库点击整行打开岗位详情弹窗，操作列未加入时提供“加入面板”，已加入时提供“查看面板”。
- 岗位详情展示列表字段、JD、投递注意事项和公司介绍。
- 岗位库筛选移除行业分类、批次和笔试，保留搜索、工作地点、企业性质和已下线开关。
- 重排投递看板列表字段为：更新时间、公司/岗位、当前阶段、下一步、内推码、操作。
- 投递看板筛选移除渠道，详情抽屉增加投递注意事项和公司介绍。
- 两张列表的更新时间支持升序/降序排序，排序在服务端生效。
- 岗位导入、Application 创建/更新 API 支持内推码、投递注意事项和公司介绍。
- 飞书同步支持第二个 Wiki 多维表格数据源；该来源不做届次/批次筛选。
- 第二数据源将“企业名称”末尾日期括号拆分为公司名和更新时间。
- 岗位库列表不展示内推码，内推码仅在岗位详情弹窗展示；操作按钮保持等宽紧凑。
- 投递看板操作列提供删除与投递；投递使用绿色成功语义样式，点击行仍可查看详情。
- 导航菜单中“投递看板”和“岗位库”互换位置。
- 全局消息提示始终显示在弹窗、抽屉与遮罩上方。
- 导入时清理行业/性质中的已知污染文本“婉清学姐冲冲冲的店唯一正版”，并清理存量数据。

## Out of scope

- 不移除数据库中既有行业、批次、笔试、渠道、薪资等字段。
- 不改变看板拖拽、状态流转、飞书授权或岗位清空行为。
- 不新增公司独立编辑页或岗位详情独立路由。

## Acceptance criteria

- 岗位库列表按指定顺序展示六列，点击行打开详情弹窗；操作列未加入时显示“加入面板”，已加入时显示绿色“查看面板”，两种状态尺寸一致。
- 点击两张列表的“更新时间”表头可在升序和降序间切换，默认最新在前且跨分页保持顺序。
- 更新时间以 `YYYY.M.D` 展示，例如 `2026.8.21`。
- 岗位库筛选区不再展示行业分类、批次和笔试控件，筛选请求也不再发送对应参数。
- 点击岗位库行打开可关闭的详情弹窗，完整展示岗位信息、投递注意事项和公司介绍；缺失值以“—”或明确空态展示。
- 点击“加入面板”首次创建投递记录；加入成功后按钮切换为绿色“查看面板”，点击后进入投递看板且不重复创建记录，按钮点击不触发行详情弹窗。
- 投递看板“投递”按钮使用绿色成功语义样式，“删除”保持红色危险语义样式。
- 侧边导航中的“投递看板”和“岗位库”位置已互换。
- 投递看板列表按指定顺序展示六列，不再展示渠道筛选。
- 投递详情抽屉可读取并保存投递注意事项、公司介绍；保存仍写 Application UPDATE 事件。
- Excel/飞书中对应列存在时可导入内推码、投递注意事项和公司介绍，缺失时保持 null。
- Wiki 链接可解析至背后的 Bitable；`荣耀(8.18开启)` 等名称导入为公司“荣耀”和当年 8 月 18 日，非日期括号不拆分。
- 飞书导出任务以 `job_status=0` 且存在 file token 作为成功，不把 `job_error_msg=success` 误判为失败。
- API 边界使用 Zod 限制新增文本字段，Prisma migration 可安全增加可空列。

## Risks and open questions

- 不同来源表头可能不一致；导入器通过中英文别名兼容常见名称。
- 公司介绍是公司级字段，同名公司的后续导入仅在来源提供非空值时更新，避免空值覆盖已有介绍。
