# F-023：素材库驱动的简历与网申编辑器

## Goal

将候选人资料收敛为“总个人档案 + 可复用素材卡片 + 文档编排”三层。总个人档案是基础事实的唯一来源；项目、校园、荣誉等方向性内容以带多版本文案的素材卡片管理；简历和网申档案只保存选用的卡片、文案版本、显示规则和版本历史。这样既能避免基础信息重复与错乱，也能让一处素材更新安全地同步到需要它的文档。

## User scenarios

1. 用户在总个人档案中维护姓名、性别、电话、邮箱、出生日期、学历、院校、专业、政治面貌和绩点；新建简历或网申档案时自动显示这些事实，无需重复填写。
2. 用户在某份简历或网申档案中临时隐藏某项基础信息；原始值不被复制或修改。用户回到总档案修改后，所有未隐藏的引用实时使用新值。
3. 用户将旧网申档案中的项目、校园经历、技能或奖项导入为待确认的素材卡片；确认后，旧档案继续保留为只读历史归档。
4. 用户为一张项目素材卡片维护标准版、精简版和岗位侧重版文案；新建简历时从素材库拖入卡片，选择文案版本并调整顺序、显示状态和技术细节。
5. 用户编辑网申档案的结构化表单，在项目经历、校园经历、奖惩和附加问答等输入框中选择卡片及其文案版本一键填充；页面持续显示字数及限制提示。
6. 用户更新一张素材卡片后，先查看受影响的简历/网申档案及差异，再明确确认按标签批量追加或同步刷新；系统创建新的文档版本，不原地改写历史版本。

## In scope

- 以 `PersonalProfile` 为基础事实唯一来源：姓名、性别、电话、邮箱、出生日期、学历、院校、专业、政治面貌、绩点。简历/网申只能配置字段隐藏规则，不能保存或编辑这些字段的覆盖值。
- 新增素材卡片库：项目、实习经历、工作经历、校园经历、荣誉奖项、技能、自我评价和自定义问答八类；卡片支持标题、可选标签、系统维护的结构化事实、可选开始/结束时间、多个命名文案版本、创建/更新时间与归档状态。
- 引用模型：简历版本与网申档案保存卡片引用、所选文案版本、排序、是否展示、精简/隐藏技术细节等呈现规则，而不是复制卡片正文。
- 简历编辑器：左侧可搜索、筛选、拖入的素材库；中间编排画布；右侧当前卡片配置。支持手动排序、显示/隐藏、文案版本选择及基础字段隐藏。保存产生新 ResumeVersion。
- 网申编辑器：基础信息、教育信息、自我评价、项目经历、校园经历、奖惩信息、附加问答等结构化区块；可在允许的文本框中插入素材卡片版本；每个受限输入框实时显示字符数与超限状态。
- 旧 `ApplicationProfile` 的项目/校园/技能/奖项等方向性 JSON 作为历史数据保留；提供“扫描并生成待确认素材卡片”的非破坏性迁移预览。只有用户明确确认的条目才创建卡片，原档案不删除、不重写。
- 影响分析与批量同步：展示卡片被哪些当前文档引用、哪些文档标签命中；用户可选择“创建更新版本”或“仅追加到选中文档”。每次批量操作必须给出受影响文档、变更摘要与确认动作。
- 简历支持导出 Markdown；PDF/Word 导出作为同一导出服务的后续实现阶段，必须基于用户已保存的版本且不修改该版本。
- 所有新增 API/服务边界均使用 Zod；用户可见的简历、网申、素材和批量同步写入均记录不可变事件或版本元数据。

## Out of scope

- 自动或无确认地修改任何简历、网申档案、旧档案或外部招聘网站表单。
- 在简历/网申中覆盖、复制或直接编辑总个人档案的基础事实；基础事实只能在总个人档案中编辑。
- 自动用 AI 推断、编造或改写素材事实；后续 AI 只能在用户明确授权的卡片与证据范围内生成候选文案。
- PDF/DOCX 文件导入、在线版式模板市场、多人协作、云端实时协同、自动投递及招聘网站自动填写。
- 直接覆盖已有不可变 ResumeVersion；所有编辑和同步都创建新版本或草稿。

## Acceptance criteria

1. 新建简历或网申档案时，基础信息和教育信息从总个人档案解析显示；简历/网申 API 不接受基础事实的原值覆盖，只接受明确的字段隐藏规则。
2. 在任意文档隐藏一项基础信息，不影响总档案及其他文档；总档案修改后，未隐藏字段在相关文档解析结果中同步更新。
3. 用户可创建、搜索、按标签筛选、编辑、归档素材卡片，并为每张卡片维护至少一个命名文案版本；实习与工作可分别选择，经历类卡片可录入开始/结束时间，用户无需理解或手写 JSON；所有文案版本可追溯且不丢失既有引用。
4. 简历编辑器支持把素材卡片加入/移出当前编排、调整顺序、选择文案版本、隐藏卡片与配置简化规则；保存后创建新版本，旧版本内容和引用不变。
5. 网申档案提供结构化区块及“插入素材卡片”操作；插入后写入该字段的卡片引用，展示实时字数，并在配置了字数上限时明确标记超限而不截断文本。
6. 旧 ApplicationProfile 的方向性经历仅以“待确认迁移项”预览；迁移确认后可创建相应素材卡片，原始 JSON 和旧档案仍可读取。
7. 任何卡片改动都不会自动写入引用它的文档；系统先列出影响范围和差异，用户确认后才为每个选中的当前文档创建新的版本，并标注同步来源。
8. 用户可按卡片标签选择目标集合，将一张卡片追加至符合标签的技术类简历或互联网岗网申档案；系统排除已包含该卡片、已归档和无权限文档，并报告创建/跳过原因。
9. 导出 Markdown 仅使用用户明确保存的简历版本；导出不会创建、更新或覆盖 ResumeVersion。PDF/Word 导出尚未实现时，UI 必须明确显示为“即将支持”。
10. 所有 API 输入与输出有 Zod 校验；跨用户、已归档或不存在的卡片/版本引用被拒绝；相关迁移、服务测试和 `pnpm typecheck` 通过。

## Affected contracts

- `specs/contracts/domain-model.md`：新增 MaterialCard、MaterialCardVariant、DocumentComposition/DocumentCardReference、文档变更事件与归档/版本规则；收紧 PersonalProfile、ApplicationProfile、ResumeVersion 的数据所有权。
- `specs/contracts/api-conventions.md`：新增素材库、文档编排、迁移预览/确认、影响分析、批量同步和导出 API。
- `specs/contracts/agent-tools.md`：限制未来 AI 只能读取用户显式授权的卡片/文案版本和事实依据，不能直接写入文档或触发同步。
- `specs/contracts/browser-extension.md`：后续解析网申表单时使用网申档案的已解析字段与素材引用，不读取页面既有值。

## Confirmed decisions

- 总个人档案是基础事实唯一来源；文档仅能隐藏，不能覆盖基础信息原值。
- 素材卡片是方向性内容的唯一可复用来源；文档保存引用与编排，不复制正文作为可编辑事实源。
- 旧网申档案非破坏性归档；素材迁移采用预览 + 用户确认，绝不自动删除或重写。
- 卡片更新和批量追加永远先影响分析、后用户确认；同步一律创建新文档版本，保留历史。
- 简历以拖拽编排为主，网申以结构化表单和按需插卡为主。
- F-023 第一阶段交付素材库、引用模型、两类编辑器与同步预览；Markdown 导出可实施，PDF/Word 导出只预留接口与 UI 状态。
- 教育事实统一存放于 `PersonalProfile.educations`，GPA 为可选显式字段；不从文档推断。
- 保存后的文档引用固定 `MaterialCardVariant`，不支持 follow-current；卡片更新只有在预览和确认后才创建新文档版本。
- ApplicationProfile 增加不可变版本；旧分类 JSON 和覆盖字段仅兼容读取，F-023 新写入不再产生这些覆盖值。
- 字符数按 Unicode code point 计算；批量同步单次最多 50 个目标并要求幂等键。
- 标签是可选的检索、岗位匹配和影响分析元数据，不直接显示在简历中；经历时间由可见表单写入结构化 facts。
- 新建素材表单随类型切换字段：项目、实习、工作、校园和荣誉分别使用符合语义的标题、角色、组织与时间标签；项目/实习/工作另有可见技术栈。旧卡继续兼容，不要求补齐。

## Risks and open questions

- 总档案当前字段与“学历/院校/专业/绩点”需要统一为教育主记录的派生事实或显式字段；实施前要确定哪种表示是唯一真实来源。
- “精简”“隐藏技术细节”必须形成确定的渲染规则，不能让系统或 AI 静默删改事实；建议卡片文案版本由用户预先维护，规则只选择已存在的安全版本。
- 批量同步可能产生大量版本，应限制单次操作数量并提供预览、幂等键和失败明细。
- PDF/Word 的稳定分页和中文字体嵌入需作为单独导出实现任务验收，不能阻塞资料模型与编辑器上线。
