# F-019: 工作台 UI 系统收敛

## Goal

保留现有雾面求职工作台的视觉方向，将首页、看板、资料页和设置页收敛到一致的表面层级、间距、表单控件与操作层级，提升可读性和编辑效率。

## User scenarios

1. 用户在首页和资料页之间切换时，卡片、按钮和表单控件具有一致的尺寸与节奏。
2. 用户编辑个人档案和网申档案时，输入框与标签清晰可辨，长表单能连续阅读。
3. 用户能一眼区分页面唯一主操作、次级操作和危险操作，不会误把删除当成主操作。

## In scope

- 定义全局表面、间距、圆角、表单、按钮和文字对比度 token。
- 调整首页、投递看板、简历版本、网申档案、个人档案和 API 设置的视觉一致性。
- 将个人档案的教育经历改为主表单内的嵌套区段；保留现有字段、保存和新增/删除交互。
- 改善桌面与窄屏下的表单、卡片和固定保存操作。

## Out of scope

- 不改变任何 API、数据模型、路由或表单字段。
- 不新增岗位库的数据导入、搜索或筛选能力。
- 不更换工作台的整体主题、品牌文案或首页信息结构。

## Acceptance criteria

1. 全站采用 4px/8px 间距刻度，主卡片为 16px 圆角，输入控件为 10px 圆角。
2. 常规输入、选择与数字输入控件高度为 40px；主按钮高度为 40px，工具按钮可为 32px。
3. 资料页的输入底色、边界、焦点和标签在暖白表面上清晰可读；辅助文字与表头不再使用低于 AA 的浅灰色。
4. 个人档案只有一个主表面；教育经历在其中作为嵌套区段呈现，删除操作为低强调危险操作。
5. 首页维持现有信息架构，仅同步卡片、文字、导航与按钮的统一规则。
6. 窄屏下导航可横向访问，表单不会产生横向裁切，双列字段退为单列。
7. `pnpm typecheck` 和 `pnpm lint` 通过。

## Affected contracts

- 无。该 Feature 仅调整前端呈现，不改变 API 或领域数据。

## Risks and open questions

- Element Plus 的内部变量会跨组件生效；通过语义化变量与资料页作用域选择器限制影响范围。
- 现有工作区未被 Git 跟踪；本 Feature 只修改明确列出的前端与交付文档文件。
