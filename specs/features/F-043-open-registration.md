# F-043: 开放注册

## Goal

让工作台从"只有所有者能登录"升级为"任何访客都能自助注册并登录"，使多用户真正可用。注册即时生效、暂不验证邮箱；新用户得到空账号，从零开始录入。注册是否开放由一个环境变量总开关控制。登录页改为独立全屏页（不套工作台菜单），风格与工作台一致；新用户直接看到共享岗位库（飞书同步仍由所有者维护）。

## User scenarios

- 陌生访客打开登录页（独立全屏、无侧边菜单），点击"注册"，填写邮箱 + 密码（可选显示名），创建账号后自动进入空工作台。
- 已退出用户可用任意已注册邮箱重新登录。
- 总开关关闭时，前端隐藏注册入口、注册接口返回明确错误；已有用户登录完全不受影响。
- 新用户登录后看到空数据（空看板、无简历 / 档案 / 画像），但岗位库能看到所有者已同步的共享岗位（只读）；其投递记录从零开始、仅自己可见。
- 每个用户的数据仍严格隔离，彼此不可见。

## In scope

- 打开 better-auth 的公开注册：`disableSignUp` 由环境变量总开关（`ALLOW_PUBLIC_SIGNUP`）控制，不再写死为 `true`。
- 登录页改为独立全屏页：使用专用布局，不套工作台侧边菜单 / 顶栏；视觉风格（配色、logo、字体）与工作台一致。
- 登录页增加注册入口 / 模式：邮箱 + 密码 + 可选显示名。
- 前端注册动作：新增 `signup()`，调用 better-auth 的 `/api/auth/sign-up/email`。
- 环境变量总开关：关闭时注册接口拒绝、前端隐藏入口；未设置时的默认值在 plan 阶段确定（倾向"默认关闭，显式开启"）。
- 新用户空账号体验：确认各数据接口 / 页面对"无数据"状态友好；确认岗位库为全局共享（Job 无 userId），新用户直接看到共享岗位、投递各自独立。
- 岗位库写权限：引入简单的"管理员"标记，只有管理员能下线 / 删除 / 导入岗位（飞书与 Excel）；普通用户对岗位库只读，但仍可把岗位转为自己的投递。

## Out of scope

- 邮箱验证、找回密码、第三方 OAuth 登录。
- 限流、配额、防滥用。
- 账号注销、删除、封禁、密码修改。
- 飞书多用户化（同步源按用户遍历、每个用户各自授权飞书）。
- 完整角色 / 权限体系（多角色、细粒度权限、后台管理界面）——本次只做"管理员 vs 普通用户"这一层最简单限制。
- 部署上线（仍走 Tailscale 内网）。
- 任何数据迁移（新用户从空开始；现有所有者账号与岗位库数据不动）。

## Acceptance criteria

- 总开关开启时，访客可注册并自动登录；关闭时注册接口被拒、前端入口隐藏，且已有用户登录不受影响。
- 登录页为独立全屏页，不含工作台侧边菜单 / 顶栏，风格与工作台一致。
- 注册后新用户进入空工作台，各页面无报错，能正常新建投递、简历、档案等。
- 新用户能看到共享岗位库（含公司信息），但投递记录为空、且仅自己能见；两个不同账号数据互不可见。
- 普通用户调用岗位库写接口（下线 / 删除 / 导入）返回 403 且不改变数据；管理员可正常操作；普通用户仍可把岗位转为自己的投递。
- 未验证邮箱也能正常使用（本次不做邮箱验证）。
- 注册接口不返回密码哈希或任何明文密钥；新用户 AI 功能默认走 BYOK，未配置 Key 时清晰报错而非静默失败。
- 全部现有测试、typecheck、lint、build 通过。

## Affected contracts

- `specs/contracts/api-conventions.md`：新增公开注册接口 `/api/auth/sign-up/email` 的说明，及总开关关闭时的错误语义；新增岗位库写接口（下线/删除/导入）的 `403 FORBIDDEN` 非管理员语义；修订 F-042 Auth API 段中"本次不开放公开注册"的表述。
- `specs/contracts/domain-model.md`：更新"MVP 用户边界"段——自 F-043 起允许多账号自助注册（仍无邮箱验证）；确认 Job/Company 为全局共享、Application 按 userId 隔离；说明"管理员"标记的存储方式（环境变量或 User 字段）。

## Risks and open questions

- **开放注册无邮箱验证与限流**：当前 Tailscale 内网风险可控，但上公网前必须先补限流与防滥用；总开关作为兜底，可随时关闭注册。
- **管理员标记的存储方式**：用环境变量 `ADMIN_EMAILS`（逗号分隔邮箱列表）还是给 User 加 `isAdmin` 字段（需迁移），plan 阶段确定；倾向环境变量（简单、无需迁移、适合当前个人工具）。
- **better-auth 注册后的自动登录**：`/api/auth/sign-up/email` 是否默认建立会话，需在 plan 阶段确认；若不自动登录，则注册成功后前端立即调用一次登录接口。
- **新用户空数据态覆盖**：需逐页检查空态处理，可能补几处"无数据"提示，避免首屏报错。
- **总开关默认值**：未设置 `ALLOW_PUBLIC_SIGNUP` 时默认关闭还是开启，倾向"默认关闭"以避免升级后意外开放，plan 阶段确认并写入 `.env.example`。
