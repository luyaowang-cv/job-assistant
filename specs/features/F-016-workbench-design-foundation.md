# F-016: 求职工作台设计基础

## Goal

在继续研发业务功能前，为个人求职全流程工作台建立统一、可实施且可验收的视觉语言、布局框架和页面信息层级，使推进求职、准备资料、面试准备与设置具有一致的导航和操作体验。

## User scenarios

1. 用户进入投递看板时，能先看到当前需要推进的机会和可执行的下一步，而不是被泛化的仪表盘信息淹没。
2. 用户在资料和简历页面编辑较长表单或文本时，内容区保持可读宽度、清晰层级和稳定的保存操作位置。
3. 用户在任意工作台页面能够理解当前所在模块、页面用途与主要操作，不需要依赖重复的大标题或冗长说明。
4. 用户能够在导航中预期找到岗位库、可视化简历版本编辑、面试准备与复盘，即使这些后续页面尚未实现具体业务能力。

## In scope

- 定义工作台的信息架构、桌面与窄屏壳层行为、导航分组和页面容器宽度规则。
- 定义颜色、字体、间距、圆角、阴影、交互状态与 Element Plus 主题 token。
- 为投递看板、岗位库、简历版本、网申档案、个人档案、面试准备和 AI 设置定义页面标题区、主要操作区、内容区与保存区的布局基线。
- 定义具有求职工作流含义的签名元素：行动轨（当前阶段、下一步和临近事项的轻量表达）。
- 输出可评审的文字线框与验收标准；本 Feature 不改变任何业务流程、数据模型、API 或扩展能力。

## Out of scope

- 新增或修改职位、简历、网申、AI、数据库与浏览器扩展业务功能。
- 改写页面文案以外的领域规则，或实现数据分析大屏。
- 岗位库的外部文档连接/同步、HTML 简历编辑器、简历模板、JD 生成面试资料、面试复盘与知识库等后续独立 Feature 的实现。
- 复杂动画、暗色主题、移动端专属工作流及品牌插画。

## Acceptance criteria

1. 设计基础文档给出明确的颜色、字体、间距、容器宽度和组件层级 token，能够直接用于 Nuxt/Element Plus 实现。
2. 所有现有与已确定的后续工作台模块拥有统一页面骨架和明确的唯一主要操作；长表单内容不会无限扩展至窗口全宽。
3. 导航按照“推进求职”“准备资料”“面试准备”“系统”表达用户任务，且窄屏时不会阻断主要内容访问。
4. 行动轨只用于真实的投递阶段、下一步或时间线信息，不作为无意义装饰。
5. 设计方案明确指出与当前页面的差异、实施顺序及不改动业务能力的边界。

## Risks and open questions

- 当前页面处于功能验证阶段，真实数据密度尚不稳定；设计必须保持可扩展而不能依赖硬编码统计数据。
- 字体加载会影响本地可用性；实现优先使用可靠的系统中文字体栈，不依赖外部字体网络请求。
