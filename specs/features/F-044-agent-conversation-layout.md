# F-044: Agent 对话页布局重构

## Goal

把求职 Agent 页从"管理后台表单风"改为对标主流大模型对话界面的布局：左侧可折叠的历史对话栏，中间居中的对话列，空态是一张居中小卡片、发出第一条消息后撑满可用高度。同时把页面样式从历史遗留的违规值收敛回 `docs/UI-DESIGN-SYSTEM.md` 的令牌体系。

## User scenarios

- 用户打开求职 Agent，看到的是一个居中的小卡片（问候语、快捷提问、输入框），而不是被顶部信息模块占满的页面。
- 用户发出第一条问题后，对话区自动撑满可用高度，输入框固定贴底，历史消息可滚动。
- 用户在左侧对话栏里切换历史对话、切换岗位和简历版本、新建对话，不必再去顶部找下拉框。
- 用户屏幕较窄时，对话栏自动收起成细条，把宽度让给对话内容；也可以手动展开。

## In scope

- 移除 Agent 页面顶部的岗位与简历信息展示模块（`agent-heading`、`context-docket`）与独立的会话切换条（`session-strip`）。
- 新增 Agent 页内可折叠的左侧对话栏，承载新建对话、岗位切换、简历版本切换、历史对话列表、删除当前对话和模型状态。
- 对话列宽度上限 800px 居中，左右保留留白；页面高度撑满主内容区且不产生双层滚动条。
- 空态为垂直居中的卡片，首条消息入列后自动切换为撑满高度的标准对话区。
- 4 个快捷提问按钮移到输入框正上方，空态与激活态共用同一份输入区 DOM。
- 整块 `<style scoped>` 按设计令牌重写；同步把 `AgentMarkdown.vue` 的写死色值换成令牌。
- 响应式：≤1400px 自动折叠对话栏，≤767px 对话栏改为覆盖层并补一个打开入口。

## Out of scope

- 不修改流式打字效果、自动滚动、NDJSON 协议、消息持久化和 Provider 配置。
- 不新增或修改任何服务端 API 与数据模型；历史对话列表复用现有 `GET /api/v1/career-agent/conversations`。
- 不改动全局布局 `layouts/default.vue` 的导航侧边栏，也不做全局导航折叠。
- 不改 Element Plus 主题变量或深色模式配置。

## Acceptance criteria

- Agent 页面顶部不再出现岗位/简历信息展示模块，页面首屏直接是对话区。
- 无消息时，问候语、快捷提问和输入框构成一张垂直居中的卡片；发出第一条消息后卡片外框消失，对话区撑满可用高度，输入框贴底。
- 对话列宽度不超过 800px 且左右均有留白；1920px 宽屏下不再横向铺满，同时 `body` 与 `el-main` 均无横向滚动条。
- 页面高度等于主内容区可视高度，`el-main` 不出现第二条滚动条。
- 左侧对话栏可折叠为 56px 细条并可再次展开；≤1400px 视口自动折叠；折叠态每项仍可点击切换对话且悬停有完整标题提示。
- 历史对话列表展示标题、公司与消息数，当前对话以边框和底色标识激活；生成中列表与新建按钮禁用。
- 三个既有入口 `?applicationId=…&mode=evaluate`、`?resumeVersionId=…&mode=optimize`、`?conversationId=…` 的参数读取与预填行为不变。
- 新的样式块中不出现被 `docs/UI-DESIGN-SYSTEM.md` 禁止的圆角/间距值（6、9、11、13、14、19、20、22、28px）与紫色强调色，展开态每屏只有一个实心主按钮。
- ≤767px 宽度下对话栏默认隐藏，可通过对话区顶部按钮以覆盖层形式打开，点击遮罩或折叠按钮关闭；输入区在长对话中保持可见。
- `pnpm lint`、`pnpm typecheck`、`pnpm build` 通过。

## Affected contracts

- 无。现有 HTTP API、领域模型与流式响应协议均保持不变；本次仅调整页面布局、样式与前端派生状态。

## Risks and open questions

- 页面高度依赖父级 `el-main` 被 flex 解析出的确定高度，用 `height:100%` 取用；若浏览器表现不符合预期，退化为 `calc(100vh - 146px)`。
- `ref="conversation"` 必须始终挂在真正负责 `overflow-y:auto` 的元素上，否则流式自动滚动会静默失效，需在回归中显式验证。
- 本特性取代 F-036 中"移除 Agent 页面 1480px 最大宽度限制、不重新引入固定页面上限"的决定：F-036 是在修流式渲染时顺带放开的宽度，本次以长回答可读性优先重新收窄到 800px，并已在 F-036 标注取代关系。
- 移动端（≤767px）放弃撑满高度，改用 sticky 输入区，行为与桌面端存在有意差异。

## 已知遗留问题（本次不处理）

- **Element Plus 主题主色仍是脚手架模板的紫色 `#6b21a8`。** 来源是 `web/app/assets/scss/element/index.scss` 的 `$-colors` 里 `primary: rgba(107,33,168, 1)`，该文件是 Element Plus 生成派生色阶的源头，从模板继承后未更新。
  - `web/app/assets/scss/index.scss:46` 虽然写了 `--el-color-primary: var(--workbench-blue)`，但只覆盖主色本身；`-light-3/5/8/9`、`-dark-2` 等派生色仍按紫色计算，且 Element Plus 生成的样式表加载顺序在业务样式之后。
  - 可见后果：**主按钮的禁用态、hover 态和浅底色偏紫**，而常态因 `.el-button.el-button--primary` 的显式覆盖是绿色，同一控件不同状态配色不一致。受影响范围是全站（投递看板、素材库、简历版本等所有使用 `type="primary"` 的位置），不限于 Agent 页。
  - 修复方式：把 `element/index.scss` 的 `primary.base` 改为 `#7a9689`（对应 `--workbench-blue`），一行即可，回滚成本相同。**需单独开特性处理并全站回归**，因为会改变所有页面的主色阶。
  - 本次经确认暂不修改。
