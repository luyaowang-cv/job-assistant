# F-037: 投递看板列表分页

## Goal

让投递看板列表完整暴露服务端已有的分页数据，用户可以访问全部投递记录并切换每页条数。

## User scenarios

- 用户有 49 条投递记录时，列表显示当前页数据、总数和分页控件，可进入后续页面。
- 用户搜索、筛选或调整更新时间排序后，从第一页展示对应结果。
- 用户删除当前页最后一条记录后，页面自动回到仍然有效的最后一页。

## In scope

- 投递列表请求显式携带 `page` 和 `pageSize`。
- 增加页码、上一页和下一页控件；不在分页区域重复展示总数或每页条数选择器。
- 搜索、状态筛选、重置和排序时重置页码。
- 删除后修正可能越界的当前页。

## Out of scope

- 不修改 Application API、Zod Schema、数据库查询或领域模型。
- 不改变看板拖拽、投递详情和记录创建流程。
- 不增加无限滚动或客户端一次性读取全部记录。

## Acceptance criteria

- 请求 `/api/v1/applications` 时始终传递合法的 `page` 与 `pageSize`。
- 总数大于一页时列表下方显示分页组件，只包含上一页、页码和下一页。
- 49 条记录按每页 20 条通过 3 页完整访问，但页面不展示总数和每页条数选择器。
- 搜索、筛选、重置和排序后当前页为 1。
- 删除导致当前页越界时自动跳转到新的最后一页。
- `pnpm typecheck`、`pnpm lint`、`pnpm build` 通过，分页 API 返回正确元数据。

## Affected contracts

- 无变更。沿用 `specs/contracts/api-conventions.md` 中 F-001 Application API 的 `page`、`pageSize`、`total` 契约。

## Risks and open questions

- 高频搜索仍会产生多个请求；本次保持既有搜索交互，只修复分页可达性。
- 看板视图继续展示当前分页数据；分页组件在两种视图下均可操作，避免视图切换产生隐式全量请求。
