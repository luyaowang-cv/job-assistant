# F-003：岗位定制投递材料

## Goal

让用户针对一条已保存岗位，在其详情中生成、预览、编辑并主动保存两类投递材料：简历优化建议与可复制改写段落，以及短版、标准版、技术亮点版打招呼话术。

## User scenarios

1. 用户在某条 Application 详情中打开“投递材料”。
2. 用户粘贴当前简历文本；系统只在本次生成期间使用该文本。
3. 系统读取该岗位 JD；若已有 F-002 评估则引用其结果，否则仍可生成材料。
4. 用户预览简历修改建议、可复制改写段落，以及三版打招呼话术。
5. 用户可编辑任一初稿；仅在点击“保存材料”后，系统保存该次材料历史。
6. 用户可查看该岗位已保存材料，并知道其关联岗位、时间、Provider/模型及是否经过编辑。

## In scope

- 在 Application 详情中提供独立“投递材料”入口；不与“AI 评估岗位”混为同一操作。
- 输入为当前岗位 JD、可选最新成功 F-002 评估、临时粘贴的简历文本。
- 输出两组内容：
  - 简历优化：逐项修改建议、依据、可直接复制的改写段落；不生成完整定制简历。
  - 打招呼：短版、标准版、技术亮点版，均可复制和编辑。
- 生成后先在客户端预览；用户明确保存才创建材料历史。
- 每条材料历史保存关联 Application、生成时间、Provider、模型、结构化结果，以及“是否被用户编辑”的元数据。
- MVP 使用本地确定性 Mock Provider；无 API Key、无外部模型、无网络请求。
- Zod 校验 API 与 Provider 输入输出；所有结论只能基于 JD、当前评估和本次简历文本中的真实证据。

## Out of scope

- 保存完整简历原文、上传简历文件、基础简历或简历版本管理；这些属于后续“简历优化中心”。
- 直接生成、导出或覆盖整份简历。
- 自动发送打招呼、自动投递、修改 Application 状态，或其他外部副作用。
- JD 爬取、招聘平台访问、浏览器自动化与 MCP 搜索。
- 独立侧边栏的简历优化页面；F-003 是岗位上下文内的材料能力。
- Agent Chat 工作台、面试准备或模拟面试。

## Acceptance criteria

1. 用户可从任意未删除 Application 的详情中打开“投递材料”，且入口与岗位评估独立。
2. 服务端拒绝没有 JD 或空简历文本的生成请求；缺少 F-002 评估不阻止生成。
3. 一次生成固定返回简历优化建议、可复制改写段落，以及短版、标准版、技术亮点版打招呼话术。
4. 每项建议/改写/话术包含可识别的 JD 或简历依据；不得虚构经历、技能、数据或岗位要求。
5. 生成预览不会自动写入材料历史；关闭预览不产生数据库记录。
6. 用户可以编辑全部输出；保存后，历史标记是否发生过用户编辑，并保留用户确认后的内容。
7. 保存历史包含 Application、生成时间、Provider、模型、关联评估（如存在）和结果；同岗位可保存多条独立历史。
8. 完整 resumeText 不进入 Prisma 写入、API 响应或前端历史状态；仅可保留不可还原的摘要。
9. Mock Provider 固定标注为 `MOCK` 和版本名，且不发起网络请求；未来真实 Provider 只替换 Adapter。
10. Agent 不自动改写 Application、简历文件或外部消息；保存材料是用户明确点击后的站内写入。

## Affected contracts

- `specs/contracts/domain-model.md`：新增 ApplicationMaterial 与 AgentRun 的可选关联。
- `specs/contracts/api-conventions.md`：定义生成预览、保存材料、读取材料历史 API。
- `specs/contracts/agent-tools.md`：定义岗位材料生成工具、输入输出与无副作用边界。

## Confirmed decisions

- 简历优化采用“建议 + 可复制改写段落”，不生成完整定制简历。
- 打招呼固定输出短版、标准版、技术亮点版。
- 结果先预览，用户点击保存后才写入历史。
- 完整简历原文仅本次使用，不持久化；历史只保存结果和必要摘要。
- 必须有 JD；F-002 评估可选，存在时作为辅助上下文。
- 保存关联岗位、时间、Provider/模型、结果和编辑状态。
- 预览内全部内容都可编辑；保存后区分 AI 初稿与用户确认版本。
- F-003 继续使用本地 Mock，不接真实模型、API Key 或外部请求。

## Risks and open questions

- Mock 结果仅用于验证工作流与交互，不代表真实求职建议质量。
- 后续接入真实 Provider 前，需要单独确认模型、成本、数据传输告知与失败重试策略。
