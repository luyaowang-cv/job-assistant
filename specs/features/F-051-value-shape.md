# F-051: 值形态适配

> 属于 F-047 总纲的 P2 功能点。

## Goal

档案里存的是"事实"，页面上要的是"这个控件能接受的形状"。同一个事实在不同控件上可以是完全不同的字符串：学历「硕士」在选项里可能叫「硕士研究生」，城市「北京」在选项里叫「北京市」，薪资「20k-25k」在数字框里根本装不下。

**核对后：选项类的形态适配已经做得不错**（`OPTION_ALIASES` + 精确/别名/去省市/包含四层匹配）。真正缺的是**非选项控件**：数字框对值没有任何形状检查。

### 实测矩阵

| 场景 | 结果 |
|---|---|
| 学历「硕士」→ 选项「硕士研究生」 | ✅ 选中 |
| 学位「工学硕士」→ 选项「硕士」 | ✅ 选中 |
| 性别「男」→ 选项「男性」 | ✅ 选中 |
| 证件「身份证」→ 选项「居民身份证」 | ✅ 选中 |
| 籍贯「河北」→ 选项「河北省」 | ✅ 选中 |
| 外语等级「CET-6」→ 选项「精通/熟练/良好」 | ⚠️ 拒绝（正确——两者不是同一个事实） |
| 期望月薪「20k-25k」→ `<input type="number">` | ❌ **被写进去** |

## 找到的缺口

数字框接受的是**一个数字**。把「20k-25k」交给它，浏览器会把这个值丢掉，回读自然失败，报告于是写成"写入失败"——**把一次形状不匹配说成页面拒绝了答案**，用户拿到的信息是错的。

在规则层拦下来，才能给出对的说法：档案里存的是区间，需要你自己决定填哪个数。

## In scope

- `resolveNumericValue(value, field)`：`inputType === 'number'` 时检查形状。
  - 纯数字 → 原样写。
  - 文本里只有一个数字（"20000元"）→ 取出该数字写。
  - 有多个数字（"20k-25k"）或一个都没有 → `needs_manual`，原因写明档案里存的是什么。

## Out of scope

- **级联选择**（省/市、学院/专业）。需要多步交互与选项联动，是独立的一类控件，不在本次范围。
- **把「CET-6」映射成「熟练」**。证书等级与熟练度不是同一个事实，映射等于编造；维持拒绝。
- 日期精度：`formatDateValue` 已按控件类型与提示词处理（month / date / 分片 / 全日期），本次不动。

## 验收标准

- AC-1：`<input type="number">` 收到区间值时状态为 `needs_manual`，原因为"只接受一个数字"，且不写值。
- AC-2：同一个值在 `<input type="text">` 上仍原样写入（数字规则不误伤文本框）。
- AC-3：文本里只有一个数字时（"20000元"）取出该数字写入。
- AC-4：现有 148 条测试全绿；北森 dump 回放 `filled` 不下降。

## Risks and open questions

- **「取出唯一数字」可能取错**：例如「第 3 年 20000 元」会取出两个数字而拒绝，安全；「20k」只含一个 "20"，会被写成 20——**这是个真的坑**，k 单位没有换算。当前选择是不换算（不猜单位），因此这种情况会写错值。缓解：把「数字后面紧跟 k/K/千/万」的情况也判为需要人工确认。
- **数字框的其它约束**（min/max/step）不做检查，交给页面校验；写入后回读失败会如实报告。

## 实施记录（2026-10-19）

**先测后改**：用规则层跑了七个场景。学历/学位/性别/证件/籍贯五项由现成的 `OPTION_ALIASES` 与四层匹配正确处理；「外语等级 CET-6 → 精通/熟练/良好」被正确拒绝（两者不是同一个事实）；只有「期望月薪 20k-25k → 数字框」被直接写入。

**改动**：新增 `resolveNumericValue`，串在 `resolveOptionValue` 之后。区间值拒绝并说明档案原文；单个数字（含单位文字如「20000元」）取出数字写入；**带 k/千/万 单位的单个数字也拒绝**——写裸数字会差三个数量级，这比不填更糟。

**一轮内部修正**：第一版把单位检查放在数量检查之前，于是「20k-25k」报的是"单位需要确认"而不是"只接受一个数字"。改成先判数量、再判单位，两条消息各自对应各自的场景。

**验收**：新增 4 条用例（区间拒绝、单数字取出、k/千/万 拒绝、文本框原样）；测试 148 → **152 全绿**；北森 dump 回放 `filled 5` 不变；`card-reference-plan-check.mjs` 全部符合预期。
