# F-017: 今日工作台与独立投递看板

## Goal

把当前 `/applications` 的混合页面拆为两个明确页面：`/` 是帮助用户决定下一步的今日工作台；`/applications` 是管理全部投递记录的独立投递看板。

## User scenarios

1. 用户打开应用先看到今日重点、正在推进的机会和资料入口，而非完整的投递管理表格。
2. 用户可在首页的“正在推进的机会”中查看至多三条真实记录，并通过“查看全部投递”进入投递看板。
3. 用户在投递看板中继续使用现有搜索、筛选、列表/看板、创建、编辑、删除和拖拽状态变更能力。

## In scope

- 新建根路由工作台首页，使用真实投递数据展示今日重点、三条推进机会和资料入口。
- `/applications` 保留为独立投递看板，移除首页概览，保留完整管理能力。
- 严格复用 `visual-lab` 的组件布局与 `visual-layered` 的字体、间距、按钮、侧栏和表格视觉 token。

## Out of scope

- 不新增、删除或修改 API、数据库模型、投递状态流转和 AI 功能。
- 不实现岗位库、面试准备或外部文档同步。

## Acceptance criteria

1. 根路由不再跳转，展示首页；首页的“查看全部投递”可进入 `/applications`。
2. 首页推进机会表格为公司/岗位、当前阶段、下一步、渠道四列，只显示真实的前三条推进记录。
3. `/applications` 保留现有全部投递管理交互，并以表格为默认主视图。
4. 工作台壳层与页面字体、间距、导航选中态、主按钮颜色、卡片边界同参考基线一致，不出现 Element Plus 默认紫色主按钮或蓝色侧栏强调线。
5. `vue-tsc --noEmit` 通过。
6. 首页和投递看板复用公司/岗位、当前阶段、下一步、渠道的表格信息顺序；投递状态具有一致且可区分的语义颜色。

## Affected contracts

- 无：仅重组既有前端页面，继续调用既有投递 API。

## Risks and open questions

- 首页数据随现有筛选 API 的返回量变化；首页独立请求全部记录，不受投递看板筛选影响。
