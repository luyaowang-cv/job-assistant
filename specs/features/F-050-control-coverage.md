# F-050: 控件写入与回读覆盖

> 属于 F-047 总纲的 P1 功能点。

## Goal

五类"不是普通文本框"的控件——自定义下拉、可搜索下拉、日期分片、富文本、单选组——每一种都要能写进去、能读回来，读不回来要能说清为什么。

**核对后：五类的写入路径都已经存在**（`applyFillEntries` 有富文本与复选框分支，`applyChoiceEntries` 有单选组、原生 select、自定义下拉与远程搜索等待）。真正缺的不是路径，而是**这些路径在某些页面结构下根本不会被执行**——因为字段在规则层就没被认出来。

### 实测矩阵

| 控件 | 写入路径 | 结果 |
|---|---|---|
| 原生 `<select>` | `applyChoiceEntries` 按选项文字匹配 | ✅ 含"大学本科"这类非逐字一致的选项 |
| 单选组 | 同上，接受选项文字包含答案 | ✅ 含"男（Male）"这类带英文的选项 |
| 自定义下拉 / 可搜索 | 点开 → 输入关键字 → 等 320ms → 点选 → 回读 | ✅ 路径完整 |
| 富文本（contenteditable） | `textContent` + input/change + 延迟回读 | ✅ 路径完整 |
| 日期分片（年/月/日） | 走文本写入，值由 `formatDateValue` 按分片裁剪 | ⚠️ **段落判不出时整块放弃** |

### 找到的缺口

`SECTION_HINTS` 的教育段落只认「学校名称 / 毕业院校 / 入学时间 / 毕业时间」——**不认「教育经历」这三个字**。这恰好是最常见的区块标题。

后果：一块标题写着「教育经历」、里面只有「专业 + 起止时间」的区块，段落判不出来。普通字段还能靠别名逐字命中（`开始时间` → `education.startDate`），但**日期分片走的是"段落 + 角色"硬门槛**，段落为空就直接判成「这是日期的一部分，但无法确定它属于哪一段档案记录」——整块日期填不上。

## In scope

- `SECTION_HINTS` 的教育段落补「教育经历 / 教育背景 / 学习经历 / 学历信息 / 专业 / 学历 / 学位 / 就读」；工作段落补「企业名称 / 任职单位」。
- 用例覆盖：教育区块里的年/月分片能取到值；只有「工作经历」标题时「企业名称」仍能匹配；单选组与下拉对非逐字一致的选项能选中。

## Out of scope

- 分片月份补零（当前输出 `9` 而非 `09`）。代码里注释写明这是有意的——分片框几乎都是列着纯数字的下拉。真遇到要求补零的站点，按站点补，不全局改。
- 自定义控件的等待时长调优（`REMOTE_SEARCH_MS`）——没有真机数据前不动。
- 值形态适配（学历选项如何选、日期精度如何统一）→ F-051。

## 验收标准

- AC-1：区块标题只有「教育经历」时，年/月分片分别取到该条教育经历的年份与月份（不再报"无法确定属于哪一段"）。
- AC-2：区块标题只有「工作经历」时，「企业名称」「职位名称」仍分别取到公司与职位。
- AC-3：单选组与下拉在选项文字与答案不完全一致时（"男（Male）" / "大学本科"）仍能选中正确项。
- AC-4：现有 145 条测试全绿；北森 dump 回放 `filled` 不下降。

## Risks and open questions

- **「专业」「学历」作为段落标记可能误伤**：一个工作区块若标题里含「专业」，会被判成教育。这是用精确度换覆盖率；如果真机遇到，按站点补例外而不是回退全局。
- **段落识别变强后，其它字段的归属也可能变化**：AC-4 的回放用来确认没有把原本能填的字段挤掉。

## 实施记录（2026-10-19）

**先测后改**：用规则层直接跑五类控件的代表场景，发现四条路径都正常（含"男（Male）""大学本科"这类非逐字选项），唯独日期分片在 `context: '教育经历'` 下报「无法确定属于哪一段」。

**根因**：`SECTION_HINTS` 的教育段落只认字段名（学校名称/毕业院校/入学时间/毕业时间），不认「教育经历」这个区块标题。日期分片走 `section && role` 硬门槛，段落为空即放弃。

**改动**：`SECTION_HINTS` 两行。教育补「教育经历/教育背景/学习经历/学历信息/专业/学历/学位/就读」，工作补「企业名称/任职单位」。改动后同一份档案下分片由 `needs_manual` 变为 `filled`（2020 / 9 / 6）。

**验收**：新增 3 条用例（教育区块分片、工作区块企业名称、非逐字选项）；测试 145 → **148 全绿**；北森 dump 回放 `filled 5 / skipped_existing 11 / needs_manual 21 / 送模型 3` 与改动前一致；`card-reference-plan-check.mjs` 19 个字段全部符合预期。

**一处顺带确认**：`work.company` 的别名里早就有「企业名称」，缺的只是段落识别，所以没有改别名表。

## 真机记录（2026-10-20，北森 jlcehr 社会招聘表单）

用户导出的 45 字段结构有两处和之前不同：**整页没有区块标题**，段落只能从 `context` 里的「相邻字段」读；且同一页混着教育、工作、三个项目。

回放出两个问题：

1. **「到岗时间」被邻居拉走。** 它的相邻字段里有「学校名称」，`inferSection` 判成 education；而日期类规则不许跨段落（`rule.date` 一律否决），于是这个本来能填的字段变成「字段未匹配到档案中的可用栏目」。
2. **项目块的结束时间被判成冲突。** 无区块标题时 `education.endDate` 与 `work.endDate` 同分，分差闸门拦下——保守正确，但正确答案（`project.endDate`）在邻居里写着「项目描述」。

**修复**：`scoreRule` 的跨段落门槛增加一条例外——**`basic` 规则的精确命中（score ≥ 0.99）可以跨段落**。理由：人员层面的字段属于人，不属于某个区块；「到岗时间」挨着「学校名称」仍是本人的到岗时间。要求精确命中是为了不误伤属性字段（「工作地点」只是包含「期望工作地点」这个别名，0.8 分，仍被拦下）。

**验收**：回放 `filled` 6 → **7**，转人工 6 → 5；新增 2 条用例（到岗时间不被拉走、含糊标签仍不跨段落），并用「临时还原旧逻辑」验证过前者确实失败。测试 159 → **161 全绿**；北森 camzhaopin 回放与 `card-reference-plan-check` 均无变化。
