# 秋招求职工作台：产品与研发宪章

## 产品目标

帮助个人以低摩擦方式记录机会、准备材料、推进投递、准备面试并复盘秋招；不做自动投递或高频批量爬取。

## 技术基线

- Web：Nuxt 4、Vue 3、TypeScript、Element Plus。Nuxt 3 是原始偏好；为保留官方 Starter 的可维护基线，MVP 采用 Nuxt 4。
- 服务端：Nuxt Server Routes / Nitro，TypeScript 与 Zod。
- 数据：正式 MVP 使用 PostgreSQL + Prisma；SQLite 仅允许用于本地原型或测试。
- AI：LangChain.js + LangGraph.js；LLM 经 Provider Adapter 接入。
- 异步任务：Redis + BullMQ，仅用于耗时生成、调研和提醒。
- 浏览器插件：Chrome Manifest V3；优先 WXT + Vue 3。

## 研发流程

所有功能遵循 `Spec → Contracts → Plan → Tasks → Implement → Verify`。没有验收标准、受影响契约和验证方案的需求不得实现。

## AI 与数据安全

- Agent 只能通过受控、经 Zod 校验的工具读写当前用户数据。
- LLM 不得直接执行 SQL、文件删除或外部副作用操作。
- 简历优化和话术只能引用用户提供或明确确认的事实；不允许虚构经历、技能、数据或职位。
- 调研报告必须保存来源链接、检索日期，并区分事实与推断。
- 涉及删除、批量修改、发送外部消息的操作必须经用户确认。

## MVP 边界

当前工作台优先完成四条主线：

- 推进求职：投递看板、手动/插件录入与岗位库；
- 准备资料：HTML 简历版本与模板、网申档案、个人档案；
- 面试准备：基于已知 JD、简历、项目与实习事实的复习资料、面试复盘和可追溯知识沉淀；
- 系统：本地 AI Provider 设置。

岗位库的外部文档同步、HTML 简历编辑/模板、面试准备与复盘均须分别完成 `Spec → Contracts → Plan → Tasks` 后开发。公司调研、求职 Copilot、批量数据分析、异步任务扩展与多用户体系留在上述主线跑通后再考虑。

## 工作台体验

- 工作台首先帮助用户推进真实的下一步求职行动；界面不得为了视觉效果虚构指标、进度或紧急状态。
- 外层工作区可以适配窗口宽度，表单与长文本内容必须使用受控最大宽度、稳定留白和一致操作层级，避免无限拉宽。
- 视觉改造不得改变现有数据归属、自动化边界或外部副作用；尤其不得新增自动提交、自动跳转、自动发送或自动上传。
