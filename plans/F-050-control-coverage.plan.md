# F-050 Implementation Plan

## Architecture approach

**先测量，再决定改哪里。** 五类控件的写入路径都在，所以本功能点的价值不在于"补一个写不进去的控件"，而在于找出**为什么某些页面上的这些控件根本没走到写入**。答案在规则层：段落识别认不出「教育经历」，而日期分片依赖"段落 + 角色"的硬门槛。

**只动 `SECTION_HINTS` 的两个正则。** 教育段落补区块标题的常见写法，工作段落补「企业名称 / 任职单位」。不改 `detectSectionFromText` 的调用顺序，也不引入新的推断层——多一层就可能把原本对的判成错的。

**用三条用例锁住效果**：教育区块的分片日期、工作区块的「企业名称」、以及"选项文字与答案不完全一致"时的选择。第三条不是新行为，是给已有能力补一条回归——它此前没有任何测试覆盖。

## Contract changes

- `specs/contracts/browser-extension.md` 新增 F-050 段：五类控件的写入路径与回读方式、教育/工作段落新增的标记词、以及"分片月份不补零"这条已有约定的确认。

## Implementation sequence

1. 契约：补 F-050 段。
2. `SECTION_HINTS` 教育段落补词、工作段落补词。
3. 三条用例。
4. 跑全量测试与回放，确认没有字段被段落重判挤掉。

## Risks and mitigations

- **段落误判**：教育与工作都在 `SECTION_HINTS` 里，教育在前。一个含「专业」的工作区块会被判成教育。缓解：AC-4 的回放比对；真机发现后按站点补例外。
- **改动影响面大**：`SECTION_HINTS` 被 `inferSection` 与 `sectionFromIdentifier` 共用，几乎所有字段的段落判定都经过它。因此改动后必须跑全量测试 + 回放，不能只看新用例。

## Verification strategy

- 单元：AC-1 ~ AC-3 三条用例。
- 回归：145 条基线全绿；北森 dump 回放 `filled` 不下降（这是段落改动的唯一有效护栏）。
- 真机：在大易页面上，教育区块的起止时间应能填上（此前整块为空）。
