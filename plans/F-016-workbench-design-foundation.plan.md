# F-016 Implementation Plan

## Architecture approach

先将布局与视觉规则沉淀为系统级设计 token 和页面骨架，再将现有页面逐个迁移。默认工作台是桌面优先的个人工具：左侧导航承载“推进求职 / 准备资料 / 面试准备 / 系统”模块切换，右侧采用受控宽度的玻璃内容轨；每页仅放置一个主要操作。设计不增加任何服务端状态或数据请求。

## Contract changes

- 产品宪章补充：工作台界面以推进真实求职行动为中心，使用受控内容宽度和一致的保存/编辑层级；不得因视觉改造新增自动外部行为。

## Implementation sequence

1. 记录设计方向、token、布局线框和验收准则。
2. 补充产品宪章中的界面体验原则。
3. 建立全局 token 与应用壳层：导航、顶栏、内容宽度和窄屏回退。
4. 依次迁移投递看板、简历中心、网申档案、个人档案、API 设置的页面骨架。
5. 使用真实/fixture 数据进行桌面和窄屏视觉验收，运行 typecheck 与 build。

## Risks and mitigations

- 全量同时重写会遮蔽已有功能回归：每次迁移只改变结构与样式，保留事件、字段和 API 调用。
- 资料页字段较多：使用同一内容轨与分段节奏，而非嵌套多层卡片或无限宽网格。
- 固定保存栏可能遮挡内容：仅在编辑型页面采用，并为主体预留底部安全空间。

## Verification strategy

- 依据设计文档逐项人工检查页面壳层、宽度、层级、键盘焦点和 768px 窄屏回退。
- 回归现有保存、弹窗、抽屉、列表和拖拽交互。
- 运行 `corepack pnpm typecheck` 与 `corepack pnpm build`。
