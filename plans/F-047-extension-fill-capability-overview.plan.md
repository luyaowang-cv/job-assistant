# F-047 Implementation Plan（总纲级路线）

> 本文件只写**跨功能点的共同决策、执行顺序与收敛方式**。每个功能点开工时另写自己的 `F-0XX.plan.md`，写清那个功能点内部的架构选择与任务拆分；本文件不重复。

## Architecture approach

三个判断决定了所有功能点怎么做，先在这里定死，避免各功能点各自发明一套。

**一、准确性靠机制，不靠例外。** 现在挡住「紧急联系人电话被写成本人号码」的是 `isDescriptorCompatible` 里一行正则，加上 `GENERIC_ALIASES` 只在段落已知时才生效——两处巧合，新增一条规则就可能重新引入。所有准确性功能点共享一个原则：**规则层宁可返回空（交给下一层或标为待办），也不可写入一个"看起来合理"的值**。因为结构化取值是终局答案，写错之后没有任何一层会回头纠正它。归属域（F-048）、分差闸门（F-048）、记录身份（F-049）都是这条原则的不同落点。

**二、界面层不做判断，只反映判断。** 进度、三色标记、报告分区（F-054）全部由已经算出来的状态驱动，不引入任何"为了好看"的推断。这与产品宪章「界面不得虚构指标或状态」一致：橙色只能标在确实需要人做决定的字段上。

**三、速度来自删掉重复劳动，不来自并发。** 一次填写目前做两轮全页扫描与两轮规则匹配，第二轮只为回答"刚才写进去的值页面认了吗"，而这个问题用一次轻量回读就能回答（F-052）。**不做并行 AI 请求**——整页一次流式请求是 429 换来的结论，不倒退。

**跨功能点的共享改动只有一处**：`form-page-bridge.js` 会在 F-049 引入"稳定身份"、在 F-050 扩写控件、在 F-054 加三色标记。这三件事都在同一个文件里，所以 F-049 定下的身份契约必须让后两个沿用，不得各自再加一套 id 体系。

## Implementation sequence

1. **契约先行**：`browser-extension.md` 新增 F-047 总纲段（能力模型、归属域、稳定身份、三色标记的跨功能点约定），并把「已知局限」里本次不做的事项标注清楚。之后每个功能点开工时再补该功能点自己的契约段。
2. **P0 三连**：F-048 → F-049 → F-052。这三个决定"会不会填错、会不会串位、慢不慢"，做完就能在真实页面上验收一次。
3. **P1 三连**：F-053 → F-054 → F-050。顺序写与进度标记会让填写过程可见，之后才谈得上判断"控件写得对不对"。
4. **P2 三项**：F-051 → F-055 → F-056。长尾适配与工程化，依赖前面定下的身份与回读契约。
5. **每完成一个功能点**：跑 `pnpm test` + `pnpm build`，用真实 dump 回放一次，把实测数值回写该功能点 spec 的验收段；全部完成后回写本总纲的「当前基线」表。

## Risks and mitigations

- **功能点之间互相返工**：F-049 的稳定身份是 F-052/F-053/F-054 的共同底座，若身份定义反复，后面三个都要改。缓解：身份契约在 F-049 里一次定死并写进契约文档，后续功能点只能沿用。
- **归属层误伤**：域判定只在否定方向生效（"这不是本人的"），认不出默认本人；误伤表现为"该填没填"，可接受且可发现。真正的风险是**误判成本人以外的域**，因此域判定结果必须写进报告原因，而不是留一个空值。
- **速度目标与准确性冲突**：去重复扫描（F-052）后，若写入期间页面重排，回读可能对不上。缓解：回读匹配不到就记「未能确认」并按失败处理，**宁可多报失败，不可虚报成功**。
- **总纲目标被功能点稀释**：九个子项各自达标但整体没变化。缓解：每个功能点完成后回写 G1–G6 中的对应数值，总纲基线表是唯一的全局视图。
- **范围蔓延**：新站点适配（F-056 之外的"顺手加个站"）不进入任何功能点，走独立流程。

## Verification strategy

- **分功能点验收**：每个功能点的 spec 里写 3–6 条可执行验收，tasks 里每条对应一个 `Verify:`。
- **回放**：每完成一个 P0/P1 功能点，用 `docs/diagnosis-scripts/dumps/beisen-zhiye-camzhaopin.json` 与大易页面导出结构各回放一次，比对 `filled / needs_manual / 冲突` 计数，确认没有把原本能填的字段挤进人工。
- **真机**：至少在大易 `resumeOperation` 与一个北森页面上各跑一次「只填空白项」与「AI 填写」，逐项核对。
- **质量门**：`pnpm test`（基线 124 条不退化）、`pnpm build` 全绿；契约文档与实现一致。
