# P0.5：开源复用选型与落地清单

## 决策目标

以最少的基础设施开发时间交付“可展示、可实际使用”的单用户秋招工作台。复用经过许可核查的开源底座；自研只聚焦求职领域模型、工作流、平台适配和产品交互。

## 最终采用

| 层 | 来源 | 许可证 | 采用方式 | 原因 |
|---|---|---|---|---|
| Web 主工程 | element-plus/element-plus-nuxt-starter | MIT | 直接作为 web/ 的 Nuxt 3 + Element Plus 根底座 | 同时满足 Nuxt Server API 与 Element Plus，不需要 Vite→Nuxt 二次迁移 |
| 后台 UI 模式 | un-pany/v3-admin-vite | MIT | 选择性复用布局、侧栏、表格筛选、主题和 Pinia 组织方式 | 已实现成熟后台交互；不复制其 Vite 根工程 |
| 浏览器插件 | wxt-dev/wxt | MIT | 使用 WXT Vue 模板初始化 extension/ | 内置 Manifest V3、TypeScript、HMR 与文件式入口 |
| Agent 工作流 | langchain-ai/langgraphjs-studio-starter + langgraphjs | MIT | 复制图定义、工具 schema、流式与人工确认模式，改造成求职 Agent | 官方、TypeScript、适配受控工具和可观测 Agent |
| SSD 流程 | GitHub Spec Kit | MIT | 采用 Constitution → Spec → Plan → Tasks → Analyze → Implement 流程，保留本项目中文契约 | 防止 AI 开发脱离需求和验收标准 |

## 明确不采用

| 来源 | 原因 |
|---|---|
| career-agent 的 React/FastAPI 代码 | 技术栈不匹配；只借鉴其职位看板、爬虫边界、材料生成和日志设计 |
| 完整 V3 Admin Vite 根工程 | 基于 Vite；整体复制会失去 Nuxt Server API，造成第二次迁移 |
| langgraphjs-gen-ui-examples | 上游已归档，不作为新项目基础 |
| 自动投递/批量爬虫项目 | 与产品边界和平台风险不符 |

## 目标工程结构

- web/：直接基于 Element Plus Nuxt Starter；包含 app/、server/、prisma/。
- extension/：直接基于 WXT Vue 模板；包含 entrypoints/ 和 components/。
- specs/、plans/、tasks/、docs/research/：SSD 研发产物。

MVP 初期不引入 pnpm workspace 或多 package monorepo；Web 与插件分别独立构建，通过 REST API 协作。

## 复用边界

### 直接复制并改造

1. Element Plus Nuxt Starter 的 Nuxt 配置、SSR/客户端配置、Element Plus 接入、Docker 基础配置与目录结构。
2. WXT 的 Vue Popup、Content Script、Service Worker 入口与 Manifest 生成配置。
3. LangGraph Studio Starter 的 Graph 定义、Zod 工具 schema、流式事件与人工确认模式。

### 选择性参考/迁移

1. V3 Admin Vite 的 Layout、菜单、表格筛选、Pinia Store 与错误/空状态交互。
2. career-agent 的看板状态设计、职位去重、材料生成流程和插件数据采集体验。

### 必须自研

1. 求职领域模型：Company、Job、Application、ApplicationEvent、Interview、AgentRun。
2. 北京 / 前端开发 / Agent 开发 / AI 前端开发 / 公司类型等个人偏好筛选规则。
3. JD 解析、匹配证据、投递优先级、打招呼话、简历建议组成的 LangGraph 工作流。
4. BOSS 直聘 DOM 适配器；官网和牛客的通用结构化数据/正文兜底解析。
5. Chrome 插件与工作台 API 的数据契约。

## 许可与溯源规则

- 采用前将来源 URL、许可证、采用范围和锁定 commit 记录在本文件。
- 原样复制的文件保留原始版权与许可证声明。
- 改造后的文件在顶部注明来源与本地变更。
- 不复制未知来源、归档后无维护保障或许可证不清晰的代码。
