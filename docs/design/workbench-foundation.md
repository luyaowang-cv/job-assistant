# 求职工作台：界面设计基础

## 设计定位

**产品**：个人求职的行动控制台。  
**使用者**：同时推进多条机会、维护多份材料、需要在真实招聘网站上完成网申的个人求职者。  
**页面的核心工作**：帮用户决定并完成下一步，而不是模拟企业招聘 CRM 或展示泛化数据大屏。

## 已确认的前端基线：雾面分层卡片工作台

以 [`web/public/visual-lab/index.html`](../../web/public/visual-lab/index.html) 的组件布局为基线，并复用 [`web/public/visual-layered/index.html`](../../web/public/visual-layered/index.html) 的近白雾面背景。前者的侧栏、顶栏、卡片矩阵、信息密度和圆角节奏是后续正式页面复用的依据；后者只提供背景与半透明层次的色彩规则。其他 `visual-*` 页面仅保留为备选探索，不得混入正式实现。

求职不是一次性填写表单，而是一段反复推进、等待、补材料与复盘的过程。界面借用“行动档案夹”的秩序感：近白色雾面画布的四角仅有极淡灰蓝、奶杏、薄荷和淡紫渗透；暖白半透明卡片以阴影、边界和少量受控重叠形成空间层级。颜色不是大面积装饰，必须让文字和下一步行动先被看见。

### Signature：行动轨

行动轨是一条只承载真实时间/阶段信息的细线：投递看板的状态、详情的下一步日期、资料页的保存状态均可使用相同的左侧标记或顶部状态条。它不是数据大屏装饰；没有真实下一步时不显示。

## Token

### Color

| 名称 | 值 | 用途 |
| --- | --- | --- |
| Ink | `#3D464B` | 主文字、重要标题 |
| Slate | `#7F898D` | 次级文字、说明 |
| Mist | `#F2F3F0` | 近白雾面应用背景 |
| Cloud | `rgba(255,254,251,.48)` | 暖白半透明卡片 |
| Archive blue | `#7589A4` | 当前导航、信息型焦点 |
| Signal amber | `#D7A995` | 需注意的资料/时间状态 |
| Progress green | `#8FBA9E` | 完成/可推进状态 |
| Lilac haze | `rgba(231,224,244,.43)` | 背景边缘的低优先级透色 |

红色仅用于不可恢复或明确错误状态；不作为常规强调色。状态颜色必须同时有文字和图标/形状表达，不能只靠颜色。

### Type

- Display：`"Source Han Serif SC", "Noto Serif SC", "Songti SC", serif`，只用于模块级标题和少量关键空状态，字重 600。
- Body：`Inter, "PingFang SC", "Microsoft YaHei", sans-serif`，正文与表单 14–16px。
- Utility：`"SFMono-Regular", Consolas, monospace`，日期、状态码、API 模型等小型技术信息，12–13px。

外部字体不作为运行依赖；缺失时使用系统字体栈。

### Spacing and shape

| Token | 值 | 用途 |
| --- | --- | --- |
| `space-1` | 4px | 图标与微型内容 |
| `space-2` | 8px | 紧密字段/标签 |
| `space-3` | 12px | 卡片内部节奏 |
| `space-4` | 16px | 组件间距 |
| `space-6` | 24px | 页面分区 |
| `space-8` | 32px | 内容轨垂直节奏 |
| `radius-sm` | 8px | 输入、标签 |
| `radius-md` | 16px | 毛玻璃面板、抽屉内分区 |

应用背景使用 `visual-layered` 的近白雾面四角径向透色；不得替换为高饱和渐变或同时使用多个显眼色块。卡片采用暖白半透明（约 `48%`）与 `blur(18px)`，白色细边界和极轻阴影；表格、输入与编辑器仍使用更高不透明度，避免毛玻璃损失可读性。圆角有节制，不使用高光渐变或无语义漂浮装饰。

## Layout

### App shell

```text
┌────────── 玻璃导航轨 248px ──────┬──────────── 工作区 ────────────┐
│ 求职工作台                        │ 当前模块                本地模式 │
│                                    ├───────────────────────────────┤
│ 推进求职                          │                               │
│  ● 投递看板                       │  页面标题 + 1 个主要操作        │
│  ○ 岗位库（规划中）               │  简短、操作性说明               │
│                                    │  ───────────────────────────    │
│ 准备资料                          │        受控玻璃内容轨            │
│  ○ 简历版本                       │  max 1180px（表单 960px）       │
│  ○ 网申档案                       │                               │
│  ○ 个人档案                       │                               │
│                                    │                               │
│ 面试准备                          │                               │
│  ○ 准备与复盘（规划中）           │                               │
│                                    │                               │
│ 系统                              │                               │
│  ○ API 设置                       │                               │
└────────────────────────────────────┴───────────────────────────────┘
```

- 桌面导航宽 248px；导航与顶栏为低透明度玻璃层，模块按用户任务分组。未实现模块显示为“规划中”非交互标记，不能伪装为已可用功能。
- 主区域外层可随窗口扩展，内部 `.content-rail` 最大 1180px；表单/设置使用 `.content-rail--narrow` 最大 960px。
- 页面标题区不重复卡片标题。它提供模块眉标、页面标题、最多一行行动说明及一个主要操作。
- 768px 以下导航改为顶部横向模块入口或抽屉，内容轨两侧留白降至 16px；不得横向截断表单。

### 页面骨架

```text
模块眉标
页面标题                                      [主要操作]
当前页面下一步 / 状态（可选；真实行动信息）
────────────────────────────────────────────────────────
内容区：数据 / 表单 / 看板 / 编辑器
```

编辑页的保存操作固定于内容轨底部，并为页面主体保留 96px 底部空间。浏览页不出现粘性保存栏。

## 模块映射

| 模块 | 页面唯一工作 | 主操作 | 内容布局 |
| --- | --- | --- | --- |
| 投递看板 | 推进机会 | 新增投递 | 筛选条 + 行动轨看板；列表作为同级视图 |
| 岗位库（后续） | 搜索和筛选可投机会 | 导入/同步岗位源 | 全宽高可读表格；筛选器固定在表头，不做卡片墙 |
| 简历版本 | 维护并派生版本 | 新建/保存基础简历 | 左侧版本轨，右侧 HTML 编辑/实时模板预览；模板切换归属编辑器工具栏 |
| 网申档案 | 选择投递策略与简历 | 保存网申档案 | 上方档案选择，单列策略内容，底部保存 |
| 个人档案 | 维护固定事实 | 保存个人档案 | 单张主表单；教育和联系人作为内嵌分段，不再叠加多个大卡片 |
| 面试准备（后续） | 准备、练习、复盘和沉淀 | 创建本次面试准备 | 左侧岗位/JD 上下文，右侧可编辑复习文档与复盘；知识条目按来源可追溯 |
| API 设置 | 配置本地 AI 连接 | 保存 API 设置 | 窄内容轨，连接信息 + 风险提示 + 保存 |

## 已确定的后续业务边界

### 岗位库

岗位库是“推进求职”的独立页面，呈现为可搜索、可筛选、可排序的表格。数据将来自用户后续指定并授权连接的持续更新岗位/公司信息文档，再导入或同步至本地工作台。具体文档平台、同步频率、字段映射、去重和外部写入权限必须在独立 Feature 中确定；当前不假设 Google Sheets、Notion、Airtable 或任何特定服务。

### 简历版本

简历版本是用户可编辑的 HTML 文档，而不是仅粘贴的纯文本。页面必须支持模板选择、左侧结构/版本导航、右侧实时预览和明确保存版本。模板能力与 HTML 内容模型会影响数据结构、导出和安全边界，必须作为独立 Feature 设计；固定个人资料仍来自 PersonalProfile，版本变化集中在项目、实习、技能与校园经历。

### 面试准备与复盘

面试准备页围绕一个职位/投递记录展开：基于 JD、已保存简历版本、实习/项目等已知事实生成可编辑的复习材料；面试后保存复盘，并以可追溯来源的知识条目反哺后续准备。AI 不得编造经历或将未确认推断写成事实。其数据模型、生成契约与知识库边界需在独立 Feature 中明确。

公司调研、求职 Copilot、批量数据分析与多用户体系仍留作后续，不纳入当前工作台第一阶段。

## 自我审视

本方案没有选择常见的暖奶油色/衬线大海报，也没有选择暗底荧光色或报纸栅格。毛玻璃只用于形成个人工作台的柔和层次，不用于数据表格和文本编辑器；档案蓝与行动轨来自该产品“管理真实投递行动”的语义。行动轨是唯一强调性的视觉特征，其他区域保持克制，确保长表单和真实求职信息优先。

## 验收清单

- 所有页面使用统一壳层、标题区、内容轨与基础 token。
- 内容区不再因大屏无限拉宽；表单正文最大 960px。
- 每页最多一个高优先级主操作，其余操作降为次级/文字按钮。
- 现有 API 调用、保存、弹窗、抽屉、表单、拖拽状态不因视觉改造改变。
- 键盘焦点清晰、对比度可读；`prefers-reduced-motion` 下不依赖动画表达信息。
